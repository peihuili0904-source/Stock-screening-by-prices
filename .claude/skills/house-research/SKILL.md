# 자사 리서치 리포트 분석·기록

목표는 한 번 읽고 끝나는 요약이 아니라 **하우스뷰가 시간에 따라 어떻게 바뀌는지 추적 가능한 기록**이다.

**기록은 전부 Google Drive에 둔다. 저장소(공개)에는 리포트 내용·노트·원본을 커밋하지 않는다.**

## 위치
| 용도 | Drive 폴더 | id |
|---|---|---|
| 입력: 사용자가 리포트를 올리는 곳 | `신한리서치` | `1lwsoUxQnX0LcTWo2lviPLaPKZsToRGvN` |
| 출력 루트 | `신한리서치 기록` | `1uWwGUZOMeYyK3fgfgFq9czaPNzWNwP1W` |
| 리포트별 노트 (Google Doc) | `신한리서치 기록/리포트 노트` | `1LaJHae2j--VmnhRE7UDQZtln8wcSWDh9` |
| 현황판 스냅샷 + 상태 파일 | `신한리서치 기록/현황판` | `1GQH2qbpyf0L4bc6V3TSkyBrnGYuBCaAI` |

대화에 직접 첨부된 파일은 스크래치패드에 두고 같은 절차로 처리한다 (저장소 안에 두지 않는다).

## 기록 방식: 고치지 않고 쌓는다
이 세션에는 Google Docs 편집 커넥터가 없어 Drive로 **새 파일 생성만** 가능하다. 그래서
- 리포트 노트는 리포트당 1개를 만들고 다시 고치지 않는다.
- 누적 기록은 실행할 때마다 **새 현황판 스냅샷**(`현황판 YYYY-MM-DD`, Google Doc)과 **상태 파일**(`state_YYYY-MM-DD.json`, 일반 텍스트)을 새로 만든다. 같은 날 두 번째 실행이면 `_2`, `_3` 을 붙인다.
- 이전 스냅샷과 상태 파일은 지우지 않는다 (그 자체가 이력이다). 휴지통으로 보내지 않는다.
- 최신 상태는 `현황판` 폴더에서 제목이 `state_` 로 시작하는 파일 중 가장 최근 것(createdTime 기준)이다.

## 1. 대상 고르기
1. `search_files` 로 `parentId = '1lwsoUxQnX0LcTWo2lviPLaPKZsToRGvN'` 를 페이지 끝까지 조회한다 (하위 폴더가 있으면 그 안도). id 중복은 제거한다.
2. 최신 `state_*.json` 을 `read_file_content` 로 읽어 `processed` 목록의 Drive id 와 비교한다. 처리하지 않은 파일만 대상이다. 상태 파일이 없으면 첫 실행이다.
3. 새 파일이 없으면 "새 리포트 없음"만 말하고 끝낸다. 내용을 지어내지 않는다.

## 2. 정독과 추출
`read_file_content` 로 끝까지 읽는다. 5건이 넘으면 서브에이전트에 나눠 맡긴다. 표·차트 숫자는 단위·기준일·기준(연결/별도, 12MF 등)을 원문 그대로 옮긴다.

유형: `시장전략` / `시황` / `섹터` / `기업` / `매크로·채권·환율` / `퀀트` / `기타`. 하나의 리포트가 여러 층을 건드리면(예: 산업 리포트 안의 Top pick) 모든 층에 반영한다.

리포트마다 뽑을 것:
- 메타: 발간일, 애널리스트, 팀, 유형, 제목, 원본 파일명, Drive id
- 한 줄 결론과 시각(강세/중립/약세, Overweight/Neutral/Underweight)
- 핵심 논리 — 주장마다 근거 수치
- 시장: 지수 밴드·목표치, 이익 전망, 밸류에이션, 수급·금리·환율 가정, 선호/비선호 섹터
- 섹터: 투자의견, 업황 사이클 판단, 핵심 지표(가격·물량·마진), Top pick / 비선호
- 종목: 투자의견, 목표주가(직전 대비), 기준 주가·상승여력, 실적 추정(매출·영업이익·EPS, 컨센서스 대비), 밸류에이션 방법과 적용 배수, 카탈리스트, 리스크
- 전략 행동: 비중 확대/축소, 매수 구간, 페어 트레이드, 타이밍 조건
- 리스크와 "이 전망이 틀리는 조건"

## 3. 리포트 노트 만들기
`references/report-note.md` 양식으로 마크다운을 쓰고, `create_file` (`parentId` = 리포트 노트 폴더, `contentMimeType: "text/markdown"`, `textContent`)로 올려 Google Doc 으로 변환한다. 제목: `YYYY-MM-DD_<유형>_<제목>`. "직전 하우스뷰와 비교"는 최신 상태 파일의 해당 시장·섹터·종목 항목과 비교해 쓴다.

## 4. 상태 갱신과 현황판 스냅샷
1. 최신 상태 JSON(없으면 빈 상태)을 스크래치패드에 저장하고, 새 리포트 내용을 병합한다. 구조는 `references/state-schema.md`.
   - 해당 시장·섹터·종목의 `current` 를 최신 리포트 기준으로 바꾼다.
   - `history` 에 행을 추가한다. 기존 행은 지우지 않는다.
   - `changelog` 에 직전과 같은 점·달라진 점(상향/하향/유지와 이유)을 남긴다.
   - 같은 회사 안에서 리포트끼리 충돌하면 `dissent` 에 양쪽을 적는다. 어느 쪽이 맞는지 판단하지 않는다.
   - `processed` 에 이번 리포트(날짜·유형·제목·애널리스트·원본 Drive id·노트 Doc 링크)를 추가한다.
2. `python3 -I .claude/skills/house-research/scripts/render_board.py <state.json> > <board.md>` 로 현황판 마크다운을 만든다.
3. `현황판` 폴더에 두 파일을 만든다.
   - `state_YYYY-MM-DD.json` — `contentMimeType: "text/plain"`, `disableConversionToGoogleType: true`
   - `현황판 YYYY-MM-DD` — `contentMimeType: "text/markdown"` (Google Doc 으로 변환)
4. 만든 현황판을 `read_file_content` 로 다시 읽어 표가 깨지지 않았는지 확인한다.

## 5. 보고
사용자에게는 이번에 바뀐 하우스뷰(의견 변경, 목표치 변경, 새 커버리지, 하우스 내 이견)를 짧게 보고하고, 새 현황판과 리포트 노트를 링크한다. 저장소에는 아무것도 커밋하지 않는다 (스킬 자체를 고친 경우만 예외).

## 원칙
- 리포트에 없는 숫자·의견은 쓰지 않는다. 기록자의 해석은 "기록자 메모"에만, 그렇다고 표시해서 쓴다.
- 숫자는 원문 단위 그대로, 범위는 `–` 로 쓴다 (`~` 는 마크다운 변환 시 취소선으로 깨진다).
- 모든 판단 옆에 애널리스트 이름과 발간일을 붙인다.
