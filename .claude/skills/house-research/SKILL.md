# 자사 리서치 리포트 분석·기록

목표는 한 번 읽고 끝나는 요약이 아니라 **하우스뷰가 시간에 따라 어떻게 바뀌는지 추적 가능한 기록**이다. 리포트 하나가 들어올 때마다 해당 시장·섹터·종목 파일의 "현재 하우스뷰"를 고치고, 바뀐 점은 변경 로그에 남긴다.

## 입력
| 경로 | 설명 |
|---|---|
| **Google Drive 폴더 `신한리서치`** (기본) | id `1lwsoUxQnX0LcTWo2lviPLaPKZsToRGvN`. 사용자가 신한투자증권 리서치 리포트를 여기에 올린다. `search_files` (`parentId = '<id>'`, 페이지 끝까지) → `read_file_content` 로 읽는다. |
| `house-research/inbox/` | 로컬로 받은 원본. **git 무시 대상** — 저장소가 공개이므로 원본은 절대 커밋하지 않는다. |
| 대화에 첨부된 파일 | `house-research/inbox/` 로 옮긴 뒤 같은 절차로 처리한다. |

## 1. 대상 고르기
- Drive 폴더와 inbox 의 파일 중 `house-research/index.md` 의 "처리한 리포트" 표에 없는 것(Drive 파일 id, 없으면 파일명 기준)만 처리한다. 하위 폴더가 있으면 그 안도 조회한다.
- 새 파일이 없으면 "새 리포트 없음"만 말하고 끝낸다. 내용을 지어내지 않는다.
- Drive 파일은 `read_file_content`, 로컬 PDF는 `pdftotext -layout` (없으면 `pdf` 스킬)로 끝까지 읽는다. 표·차트 숫자는 단위·기준일·기준(연결/별도, 12MF 등)을 원문 그대로 옮긴다. 5건이 넘으면 서브에이전트에 나눠 맡긴다.

## 2. 리포트 분류와 추출
각 리포트를 유형으로 분류한다: `시장전략` / `시황` / `섹터(산업)` / `기업(종목)` / `매크로·채권·환율` / `퀀트` / `기타`. 하나의 리포트가 여러 층을 건드리면(예: 산업 리포트 안의 종목 Top pick) 모든 층에 기록한다.

리포트마다 뽑을 것 (`references/report-note.md` 양식):
- 메타: 발간일, 애널리스트, 팀, 유형, 제목, 원본 파일명
- 한 줄 결론과 시각(강세/중립/약세, 또는 Overweight/Neutral/Underweight)
- 핵심 논리 — 주장마다 근거 수치를 붙인다
- 시장: 지수 밴드·목표치, 이익 전망, 밸류에이션, 수급·금리·환율 가정
- 섹터: 투자의견, 업황 사이클 판단, 핵심 지표(가격·물량·마진), Top pick / 비선호
- 종목: 투자의견, 목표주가(직전 대비 변경), 현재가·상승여력, 실적 추정치(매출·영업이익·EPS, 컨센서스 대비), 밸류에이션 방법(PER/PBR/SOTP 등과 적용 배수), 카탈리스트, 리스크
- 전략 행동: 비중 확대/축소, 매수 구간, 페어 트레이드, 타이밍 조건
- 리스크와 "이 전망이 틀리는 조건"

## 3. 누적 기록 갱신
파일 이름 규칙 (소문자·하이픈, 한글 이름은 파일 안 제목에):
- 리포트 노트: `house-research/reports/YYYY-MM-DD_<유형>_<짧은-슬러그>.md`
- 시장: `house-research/markets/<kr|us|cn|jp|eu|em|global>.md` — 채권·환율·원자재는 `rates.md`, `fx.md`, `commodities.md`
- 섹터: `house-research/sectors/<영문-슬러그>.md` (예 `semiconductors.md`, `shipbuilding.md`, `secondary-battery.md`)
- 종목: `house-research/stocks/<티커>_<영문-슬러그>.md` (예 `005930_samsung-electronics.md`, `NVDA_nvidia.md`)

갱신 방법 (`references/` 의 market/sector/stock 양식):
1. 파일이 없으면 양식으로 새로 만든다.
2. 맨 위 **현재 하우스뷰** 블록을 최신 리포트 기준으로 고친다 (기준 리포트와 날짜 명시).
3. **의견·목표 이력** 표에 행을 추가한다 (날짜, 의견, 목표치, 리포트 링크). 오래된 행은 지우지 않는다.
4. **논리 변화 로그**에 이번 리포트가 직전 시각과 무엇이 같고 무엇이 달라졌는지 적는다 (상향/하향/유지와 이유).
5. 섹터 ↔ 종목, 시장 ↔ 섹터는 서로 링크한다.
6. 같은 회사 안에서 리포트끼리 충돌하면(예: 전략팀은 반도체 비중 축소, 반도체 애널리스트는 매수) 양쪽 파일과 index 의 "하우스 내 이견"에 둘 다 적는다. 어느 쪽이 맞는지 판단하지 않는다.

## 4. 현황판 `house-research/index.md`
- 시장별 현재 하우스뷰 한 줄 표
- 섹터 의견 매트릭스 (섹터 · 의견 · Top pick · 최근 변경일)
- 종목 커버리지 표 (종목 · 의견 · 목표주가 · 최근 변경 · 변경 방향 ▲▼–)
- 최근 의견 변경 로그 (최신순)
- 하우스 내 이견
- 처리한 리포트 표 (날짜 · 유형 · 제목 · 애널리스트 · 노트 링크 · 원본 파일명)

## 5. 마무리
- 커밋 메시지: `Add house research: <날짜> <건수>건 (<유형 요약>)`. 커밋 전 `git status` 로 inbox 원본·PDF가 스테이징되지 않았는지 확인한다.
- 사용자에게는 이번에 바뀐 하우스뷰(의견 변경, 목표치 변경, 새 커버리지)를 짧게 보고한다.

## 원칙
- 리포트에 없는 숫자·의견은 쓰지 않는다. 기록자의 해석은 각 파일의 "기록자 메모"에만, 그렇다고 표시해서 쓴다.
- 숫자는 원문 단위 그대로, 범위는 `–` 로 쓴다 (`~` 는 마크다운 취소선으로 깨질 수 있음).
- 리포트 본문을 길게 그대로 옮기지 않는다 (저장소가 공개). 핵심 수치와 논리를 요약해 적는다.
- 고객·내부 전용 표시가 있는 정보, 개인 연락처, 미공개 정보로 보이는 내용은 기록하지 않고 사용자에게 알린다.
